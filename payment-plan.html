Stripe（MY 帳號）卡、FPX、GrabPay…國際客友善、API 與文件最好；用 Stripe Checkout 主機頁面（免碰卡號）

3. ⚠ 最重要的技術前提：付費牆必須在伺服器

現況（很重要）：報告是在瀏覽器端算出來的（buildReportModel 在前端執行， src/report/reportHtml.js 也在前端）。只要檔案在客戶手上，付費牆就是假的 —— 略懂技術的人可以繞過「未付款」直接產生報告。必做

收費後必須改成

  • 付費內容由 Worker 產生／解鎖：前端只送四柱 → Worker 檢查訂單已付款 → 才回傳報告 HTML／PDF。
  • 沿用你現有的授權骨架：student／teacher／helper／admin 金鑰、裝置綁定、稽核紀錄， 正好就是「授權＋履約」的基礎，不必另做會員系統。
  • 絕對不要自己碰卡號（會踩 PCI 規範）：一律用 gateway 的 hosted checkout 或 token 化。
  • 免費與付費的分界線要寫清楚：例如排盤、五行分數免費；命理分析報告、運勢頁、實體列印收費。

4. 標準付款流程（安全做法）

  1. 客戶按「購買報告」→ Worker 建立 order：order_id、商品、金額以「分」存整數、幣別 MYR。
  2. 導向 gateway 主機頁面付款。金額由伺服器決定，不信任前端送來的金額。
  3. Gateway 打 webhook 回 /api/pay/webhook：驗簽章 → 冪等處理（同一 order 只發一次貨）→ 標記已付款 → 發出金鑰／授權。
  4. 回跳頁面（return URL）不可當作付款成功依據（可被偽造）；一切以 webhook ＋伺服器回查 gateway 為準。
  5. 履約：發 有時效的簽章連結（不要把檔案直接放在公開目錄）／加購列印就建出貨單。
  6. 全程寫稽核（誰、何時、哪個 order、金額、IP）—— 你已有 audit 機制，直接沿用。

6. 合規與行政（PDPA／發票／條款）

  • PDPA（個資）：生日／時辰屬個資 → 需隱私聲明、用途說明、可要求刪除；不得拿去做其他用途。
  • 稅務／e-Invoice：LHDN MyInvois 電子發票是分階段強制（依營業額），SST 也有營業額門檻。 這部分請直接問會計師，不要靠網路片段或本文件的敘述。必問
  • 對外條款：退款政策（數位內容一經產生通常不退）、服務範圍、免責聲明 （報告已有「僅供參考、非醫療／投資／法律建議」，保留）。
  • 對外國客：標明幣別、是否含稅、退款方式與時程、客服聯絡方式。

7. 反詐欺與客服

  • 只從 webhook 認定付款；金額、幣別、order 狀態都要回查 gateway。
  • 留存發票／收據（客戶一定會要）。
  • 客服管道：WhatsApp（馬來西亞習慣）＋ 明確回覆時間（例：工作時間 2 小時內）。
  • 信用卡 chargeback：保留交付證明（下載紀錄、IP、時間戳）。
  • 濫用防治：同一裝置大量索取 → 用你現有的 rate limit／稽核加規則。

SOP-A　Phase 0：手動收款＋發碼（每次成交，約 5–10 分鐘）

目標：不動任何程式就能收錢、交付，同時累積「真的有人願意付」的證據。
步驟 1　客戶詢問（收到訊息當下）
問清楚三件事：①誰的命盤（姓名）②出生年月日＋時間（幾點幾分）③要數位還是要印出來寄
告知時間：出生時間越準越好；不確定時辰要先說「時柱可能不準」
報價（用 話術範本 A）並告知付款方式與需要多久交付
步驟 2　建單（客戶確認要買之後）
在訂單記錄表新增一列，產生 order_id（例 FP-20260929-01）
狀態填 待付款；填上客戶 WhatsApp／Email、金額、商品
把 order_id 告訴客戶：「轉帳時請在備註填 FP-20260929-01」（對帳關鍵）
步驟 3　收款確認 只認帳戶入帳
收到轉帳截圖時，仍要自己查一次銀行／DuitNow 入帳（截圖可偽造）
金額、幣別、備註的 order_id 三者都對得上
狀態改 已付款，記錄入帳時間與銀行參考號
金額不符／沒備註 → 先問客戶，不要先出貨
步驟 4　發碼（在 App 內）
【管理頁】→ 產生學生碼（依商品決定有效天數與裝置數）
把碼貼進訂單記錄表（並記下產生時間）
狀態改 已發碼
步驟 5　產生報告
用該客戶的四柱排盤，確認「乾坤造、四柱」與客戶資料一致
列印報告 → 另存成 PDF（A4、5 頁），檔名照規則
檢查：沒有空白頁、沒有 undefined／亂碼、五行與結論都有內容
（建議）在 PDF 加上「客戶姓名＋order_id」浮水印或頁尾
步驟 6　交付
用 話術範本 C 發送：金鑰＋PDF＋簡短使用說明（點哪裡看報告）
若客戶要印出來：改走 SOP-C（先問地址再寄）
狀態改 已交付，記錄交付時間與管道
附上收據／發票（依你的稅務安排）
步驟 7　售後（交付後 7 天內）
問一句使用體驗（1–10 分）＋「有沒有看不懂的地方」
請客戶同意後留下見證（截圖可公開的部分）
把常見問題補進話術範本

SOP-B　Phase 1：自動化收款（Billplz／Stripe，1–2 週）

B-1　決定 gateway 並申請
Billplz（FPX 為主、馬來西亞轉換率高）或 Stripe MY（國際客友善）擇一先用
取得 API key／webhook secret，存在 Cloudflare 的 secret（wrangler secret put），不要寫進前端
在 gateway 後台設定 return URL 與 webhook URL
B-2　伺服器端（Worker）
新增 POST /api/pay/create：建立 order（金額由伺服器定）→ 回傳 gateway 付款連結
新增 POST /api/pay/webhook：驗簽章 → 查訂單 → 冪等 → 標記已付款 → 發碼
新增 GET /api/pay/status?order_id=：前端只讀狀態，不做授權判斷
報告改由 POST /api/report 產生：先驗訂單已付款才回傳 HTML／PDF
下載連結用有時效的簽章 URL；檔案不放公開目錄
所有狀態變化寫入稽核（沿用既有 audit）
B-3　必測（缺一不可）
付款成功 → 只發一次碼（重複 webhook 不會重複發）
改動前端金額 → 伺服器仍照自己的金額收（不可被改價）
偽造 return URL（未付款直接跳回）→ 仍視為未付款
未付款直接打 /api/report → 回 402／403，不吐內容
webhook 亂序／延遲到達 → 狀態不亂
退款後 → 授權失效、報告不可再產生
沙盒測過 3 種情境（成功／失敗／取消）才上正式金鑰
B-4　上線
先用小額真實付款自測一次（RM1），全程走完並對帳
把 gateway 的「付款成功通知」也開給自己（雙重確認）
公告退款政策與客服時間

SOP-C　實體列印出貨（每筆約 30–60 分鐘＋物流時間）

C-1　收件資料（付款後才索取）
姓名、聯絡電話、完整地址（含郵遞區號）、指定收件時段
告知用途（僅用於寄送）與保存期限（PDPA）
地址請客戶用文字回傳（不要只傳語音，避免聽錯）
C-2　列印規格
A4、彩色、雙面或單面（先講好）、紙張 80g 以上
封面頁（客戶姓名＋日期）／裝訂（騎馬釘或膠圈）
隨附一頁「怎麼看這份報告」的導讀（可重複使用同一張）
出貨前逐頁對一次：姓名、四柱、頁數、有無空白頁
C-3　包裝與寄送
防水袋／厚紙板保護，避免折角
選物流（PosLaju／J&T 等），記錄追蹤號到訂單表
寄出後立刻發追蹤號給客戶（話術範本 D）
狀態於訂單表備註「已寄出＋追蹤號」

SOP-E　例外與爭議處理

情況處理方式
付款了但沒收到碼查訂單表狀態 → 查帳戶入帳 → 若已入帳立即補發（並在備註記錄補發原因）
重複付款不自動退；先告知會全額退回多收的一筆，並記錄退款時間與參考號
金額不足先問客戶是否補差額，不要先生產報告
客戶要求退款數位內容已產生：原則上不退（事先寫明）；尚未產生／未交付可全額退。實體已寄出：不退運費
信用卡爭議（chargeback）提交交付證明：訂單、付款紀錄、下載／交付時間戳、對話紀錄
客戶對解讀不滿意區分「不滿意」與「沒收到」；可提供一次免費補充說明，但不承諾改結論
客戶給錯出生時間重算一次免費或酌收工本費（先寫在價目表）；major 差異要先說明時柱會變
懷疑盜用他人身分下單要求付款人與命主關係確認；必要時退款婉拒
